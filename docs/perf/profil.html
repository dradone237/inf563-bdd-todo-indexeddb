Ce que montrent les mesures

  • Au repos (application servie, k6 lancé, aucune charge) : processeur 7,7 %, RAM 10,88 Go utilisés sur 12,8 Go (86,9 %).
  • Au palier 4 (100 utilisateurs HTTP + 4 navigateurs) : processeur 47,4 % en moyenne (pic 52,8 %), RAM 11,20 Go (+0,32 Go par rapport au repos).
  • Processeur : il suit la charge, de 7,7 % au repos à 47,4 % au palier 4, soit environ 7,9 points de processeur pour 100 requêtes par seconde. L'injecteur (k6 et ses navigateurs) tourne sur la même machine : ce total inclut sa propre consommation (la répartition par processus se lit en direct dans Glances).
  • RAM : elle ne suit pas clairement le nombre de navigateurs (régression sur les 4 paliers : 26 Mo par navigateur, mais R² = 0,23, donc peu fiable). Avec 86,9 % de RAM déjà utilisés au repos, la RAM de la machine fluctue d'elle-même (gestion de la mémoire par Windows, autres applications ouvertes) : le coût de quelques navigateurs se perd dans ces variations (environ ±0,5 Go). Pour le mesurer, fermer les autres applications avant le test.
  • Coude (cours : « jusqu'où le système suit-il ? ») : aucun. La latence p95 reste entre 1,6 et 2,6 ms et le parcours complet dans un navigateur entre 2,59 et 2,64 s, alors que le processeur a été multiplié par 6,1 : la capacité de la machine n'est pas atteinte à 100 utilisateurs HTTP + 4 navigateurs.
  • Le serveur ne fait que servir 5 fichiers statiques : la latence HTTP p95 reste sous 300 ms à tous les paliers (1,6 ms, 2,0 ms, 2,6 ms, 2,3 ms).
  • Loi de Little (système fermé, N = X × T) : au palier 4, X = 99,9 itérations/s × T = 1,003 s ≈ 100,2 utilisateurs, pour 100 utilisateurs HTTP configurés : les mesures sont cohérentes.
